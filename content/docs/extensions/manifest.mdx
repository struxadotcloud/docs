---
title: Manifest Reference
description: Complete reference for the manifest.json file that every Struxa extension must include.
---

Every extension must include a `manifest.json` at the root of its `dist/` output. The host validates this file on install and on every boot.

## Top-level fields

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `string` | yes | Unique extension identifier. Lowercase letters, digits, and hyphens only (`[a-z][a-z0-9-]{1,62}`). Used as a URL segment and DB table prefix. |
| `name` | `string` | yes | Human-readable display name shown in the admin UI. |
| `version` | `string` | yes | Semver version string (`1.2.3`). Must increase on every publish. |
| `description` | `string` | no | Short description shown in the Discover grid. |
| `author` | `string` | no | Author name shown in the extension card. |
| `struxaApi` | `string` | yes | Semver range of the Struxa API this extension requires (e.g. `"^1.0.0"`). The host rejects extensions whose `struxaApi` range does not match the running panel version. |
| `permissions` | `string[]` | no | List of capabilities this extension requests. Defaults to `[]`. |
| `messages` | `object` | no | Map of locale code → relative path to a translated messages JSON file. |
| `ui` | `object` | no | UI configuration — pages, widget slots, server settings rows, and admin settings tabs. |

## Permissions

The `permissions` array declares every capability the extension needs. The host grants only what is listed; accessing an undeclared capability is silently ignored (no error thrown).

| Permission | What it grants |
|---|---|
| `db:own` | Drizzle DB client (`ctx.db`) for tables prefixed `ext_<id>_` |
| `api:public` | oRPC `publicProcedure` builder (unauthenticated routes) |
| `api:protected` | oRPC `protectedProcedure` builder (session required) |
| `api:admin` | oRPC `adminProcedure` builder (admin role required) |
| `hook:<event>` | Subscribe to the named panel event via `ctx.hooks.on(event, fn)` |
| `core.metadata:server` | Read/write the extension's namespace in the `server.metadata` JSON column |
| `core.metadata:node` | Same for `node.metadata` |
| `core.metadata:user` | Same for `user.metadata` |
| `settings:<prefix>` | Scoped key/value store via `ctx.settings` |
| `output:<entity>:<field>` | Publish a computed value that replaces a named UI field (e.g. `output:server:address`) |

<Callout type="warn">
  Request only the permissions your extension actually uses. Users see the full permission list before installing and may decline extensions that request more than they need.
</Callout>

## Messages (i18n)

Declare a map of locale codes to relative file paths. The host loads the matching file at request time and merges it under the `ext.<id>` namespace so host-rendered parts of your extension (nav labels, settings labels) are automatically translated.

```json
{
  "messages": {
    "en": "messages/en.json",
    "pl": "messages/pl.json",
    "de": "messages/de.json"
  }
}
```

Each messages file is a flat or nested JSON object:

```json
{
  "nav": {
    "title": "My Extension"
  },
  "settings": {
    "apiToken": "API Token"
  }
}
```

Inside iframe UIs, call `bridge.t("nav.title")` to resolve keys — see [Building Extension UI](/extensions/ui#translations).

## UI pages

Each entry in `ui.pages` registers an iframe page in the panel:

```json
{
  "ui": {
    "pages": [
      {
        "route": "/my-ext",
        "section": "panel",
        "label": "My Extension",
        "icon": "Blocks"
      }
    ]
  }
}
```

| Field | Type | Description |
|---|---|---|
| `route` | `string` | URL path (must start with `/`). The extension's `dist/web/` is served at this path. |
| `section` | `"panel"` \| `"admin"` | Which sidebar the entry appears in. `"panel"` is the user-facing sidebar; `"admin"` is the admin section. |
| `label` | `string` | Sidebar label. May be a literal string or an i18n key resolved under `ext.<id>.*`. |
| `icon` | `string` | Lucide icon name (e.g. `"Blocks"`, `"Server"`, `"Wrench"`). |

## Widget slots

Each entry in `ui.slots` injects a widget iframe into a named panel slot:

```json
{
  "ui": {
    "slots": [
      { "slot": "server.overview.after", "widget": "/my-ext/widget" }
    ]
  }
}
```

| Field | Type | Description |
|---|---|---|
| `slot` | `string` | Named injection point in the panel UI. |
| `widget` | `string` | Route to the widget's `dist/web/<widget>/` directory. |

Available slots:

| Slot | Location |
|---|---|
| `server.overview.after` | Below the full server overview on the console page |
| `server.stats.after` | Bottom of the stats sidebar on the console page |
| `server.settings.general.after` | After the General card on the server settings page |
| `server.settings.sftp.after` | After the SFTP card on the server settings page |
| `server.settings.sidebar.after` | Bottom of the sidebar on the server settings page |

## Server settings rows

`ui.serverSettings` injects settings rows into the server settings page under a card named after your extension. Values are stored in the server's `metadata` column under your extension's namespace and are readable at runtime via `ctx.coreMeta.server.get(serverId)`.

Requires the `core.metadata:server` permission to be granted.

```json
{
  "ui": {
    "serverSettings": [
      {
        "key": "subdomain_prefix",
        "label": "Subdomain prefix",
        "description": "Prefix used when auto-generating subdomains.",
        "type": "text",
        "placeholder": "mc"
      },
      {
        "key": "enabled",
        "label": "Enable automatic subdomains",
        "type": "toggle"
      }
    ]
  }
}
```

| Field | Type | Description |
|---|---|---|
| `key` | `string` | Storage key — alphanumeric and underscores only, unique within this extension. |
| `label` | `string` | Label shown in the settings row. |
| `description` | `string` | Optional helper text shown below the label. |
| `type` | `"text"` \| `"toggle"` | Rendered as a text input or an on/off toggle. |
| `placeholder` | `string` | Placeholder text for text inputs. |

When the user saves a row, the host fires the `server.settings.saved` hook to your extension — see [Server Entry](/extensions/server#hook-events).

## Admin settings tabs

`ui.adminSettingsTabs` adds tabs to the global `/admin/settings` page. Each tab renders natively in the host UI using the same components as the built-in settings tabs. Values are stored in the global settings table under `ext:<id>:<key>` and are readable at runtime via `ctx.settings.get(key)`.

```json
{
  "ui": {
    "adminSettingsTabs": [
      {
        "id": "cloudflare",
        "label": "Cloudflare",
        "sections": [
          {
            "title": "API Credentials",
            "description": "Connect your Cloudflare account.",
            "fields": [
              { "key": "api_token", "label": "API Token", "type": "password" },
              { "key": "zone_id", "label": "Zone ID", "type": "text", "placeholder": "abc123…" },
              {
                "key": "plan",
                "label": "Plan",
                "type": "select",
                "options": [
                  { "value": "free", "label": "Free" },
                  { "value": "pro", "label": "Pro" }
                ]
              }
            ]
          }
        ]
      }
    ]
  }
}
```

**Tab fields:**

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique within this extension. Alphanumeric, hyphens, and underscores. |
| `label` | `string` | Tab label shown in the settings tab bar. |
| `sections` | `array` | One or more `SectionCard` groups within the tab. |

**Section fields:**

| Field | Type | Description |
|---|---|---|
| `title` | `string` | Card heading. |
| `description` | `string` | Optional subtitle shown below the heading. |
| `fields` | `array` | Settings fields rendered inside the card. |

**Field types:**

| `type` | Rendered as |
|---|---|
| `text` | Plain text input |
| `password` | Password input — value is not returned to the browser if already set (shows a "configured" placeholder) |
| `textarea` | Multi-line text input |
| `toggle` | On/off toggle (stored as `"1"` or `"0"`) |
| `select` | Dropdown — requires an `options` array of `{ value, label }` pairs |

When the admin saves a tab, the host fires the `admin.settings.saved` hook to your extension with all changed key/value pairs — see [Server Entry](/extensions/server#hook-events).

## Full example

```json
{
  "id": "my-ext",
  "name": "My Extension",
  "version": "1.0.0",
  "description": "Does something useful.",
  "author": "acme",
  "struxaApi": "^1.0.0",
  "permissions": [
    "api:protected",
    "hook:server.created",
    "hook:server.settings.saved",
    "hook:admin.settings.saved",
    "core.metadata:server",
    "settings:my-ext",
    "output:server:address",
    "output:server:sftp.host"
  ],
  "messages": {
    "en": "messages/en.json"
  },
  "ui": {
    "pages": [
      { "route": "/my-ext", "section": "panel", "label": "nav.title", "icon": "Blocks" }
    ],
    "slots": [
      { "slot": "server.stats.after", "widget": "/my-ext/widget" }
    ],
    "serverSettings": [
      { "key": "enabled", "label": "Enable tunnels", "type": "toggle" }
    ],
    "adminSettingsTabs": [
      {
        "id": "config",
        "label": "My Extension",
        "sections": [
          {
            "title": "API",
            "fields": [
              { "key": "token", "label": "Token", "type": "password" }
            ]
          }
        ]
      }
    ]
  }
}
```
