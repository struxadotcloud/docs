---
title: Building Extension UI
description: How to build React-based UI pages and widget slots for a Struxa extension.
---

Extension UIs run inside sandboxed `<iframe>` elements served by the panel. The React template gives you a full TypeScript + React setup with a build tool (`struxa-ext build`) that handles bundling, the React alias workaround, and static asset copying.

## Project structure

```
my-ext/
├── src/
│   ├── main.tsx         # page entry point → dist/web/bundle.js
│   ├── App.tsx          # root component for the page
│   ├── page.html        # HTML shell (optional — default is generated)
│   ├── widget.tsx       # widget entry point → dist/web/widget/bundle.js
│   └── widget.html      # widget HTML shell (optional)
└── tsconfig.json        # for IDE type checking
```

The build tool infers entry points from `manifest.json`:
- Each `ui.pages[]` entry → looks for `src/main.{tsx,ts,js}`
- Each `ui.slots[]` widget entry → looks for `src/widget.{tsx,ts,js}`

## Entry point

Use `createExtension` from `@struxa/extension-sdk/react` to mount your app. It handles `createRoot`, removes the loading indicator, and wraps the tree in an error boundary that renders errors visibly rather than showing a blank page.

```tsx title="src/main.tsx"
import { createExtension } from '@struxa/extension-sdk/react';
import { App } from './App';

createExtension(<App />);
```

## Calling the host

Extension UIs communicate with their server entry via the **host bridge** — a structured message channel built on `postMessage`. Use `createHostClient` to get a typed client:

```tsx title="src/App.tsx"
import { createHostClient } from '@struxa/extension-sdk/client';

// Mirror the shape of your server router (input/output types only)
const client = createHostClient({
  getInfo: {} as {
    input: { serverId: string };
    output: { meta: Record<string, unknown> | null };
  },
});

export function App() {
  const [meta, setMeta] = useState<Record<string, unknown> | null>(null);

  useEffect(() => {
    client.getInfo({ serverId: 'some-id' }).then(setMeta);
  }, []);

  return <pre>{JSON.stringify(meta, null, 2)}</pre>;
}
```

`createHostClient` calls are routed through the bridge to the panel's oRPC API — the iframe never communicates directly with the database or server.

## Reading bridge state with `useHostBridge`

`useHostBridge` provides a React hook that subscribes to the bridge's reactive state (current user, current server context, theme, etc.):

```tsx
import { useHostBridge } from '@struxa/extension-sdk/react';

export function App() {
  const bridge = useHostBridge();

  return <p>Logged in as: {bridge?.user?.name ?? '...'}</p>;
}
```

The bridge state is pushed from the host whenever the context changes (e.g. user navigates to a different server). The hook returns `null` until the first message arrives.

## Widget slots

A widget is a smaller React component injected into a named slot on an existing panel page. It shares the same SDK but renders in its own iframe at a different route.

**1. Declare the slot in `manifest.json`:**

```json
{
  "ui": {
    "slots": [
      { "slot": "server.overview.after", "widget": "/my-ext/widget" }
    ]
  }
}
```

**2. Create `src/widget.tsx`:**

```tsx
import { createExtension } from '@struxa/extension-sdk/react';
import { Widget } from './Widget';

createExtension(<Widget />);
```

**3. Create the component:**

```tsx title="src/Widget.tsx"
import { useHostBridge } from '@struxa/extension-sdk/react';

export function Widget() {
  const bridge = useHostBridge();
  return (
    <div style={{ padding: '12px', border: '1px solid #ccc', borderRadius: 8 }}>
      Extension widget — server: {bridge?.server?.name ?? '…'}
    </div>
  );
}
```

The widget is automatically built to `dist/web/widget/bundle.js` and served when the slot is rendered.

## Custom HTML shell

If you need to add a font, meta tag, or third-party script, provide your own `src/page.html`. The build tool copies it to `dist/web/index.html`. The minimum required structure:

```html title="src/page.html"
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  </head>
  <body>
    <div id="boot-status">Loading…</div>
    <div id="root"></div>
    <script type="module" src="bundle.js"></script>
  </body>
</html>
```

`createExtension` removes `#boot-status` automatically once your app mounts.

## Build commands

```bash
npm run build   # one-shot build → dist/
npm run dev     # watch mode — rebuilds on file change
```

Both commands are provided by `@struxa/extension-build` (the `struxa-ext` CLI), which is a dev dependency in every React template project.

## TypeScript

The included `tsconfig.json` configures TypeScript for IDE support. The build tool uses esbuild for compilation, so `tsc --noEmit` (type-check only) is the recommended way to validate types in CI:

```bash
npx tsc --noEmit
```
